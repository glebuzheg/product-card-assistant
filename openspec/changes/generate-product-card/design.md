# Design

## Context
См. proposal.md и согласованный docs/design.md. Проект новый, существующего кода нет. OpenSpec 1.15.0 уже инициализирован.

## Goals / Non-Goals
Goals: простой API и проверяемая генерация. Non-Goals: универсальная LLM-платформа, CMS, парсер всего каталога, абсолютная гарантия смысловой достоверности.

## Decisions
- Python 3.12+, FastAPI /docs вместо отдельного frontend; Pydantic strict-модели, uv lock.
- product_cards/schemas.py: модели входа и результата; generation.py: промпт, проверки и OpenAI; api.py: HTTP и безопасные ошибки.
- Один lifespan-клиент AsyncOpenAI, timeout 45 секунд и max_retries=0. Ключ и модель из окружения; вызовы только при достаточных данных.
- Внутренний ответ модели: готовые тексты и evidence: block, claim, source_field, source_quote. Проверка цитат и числовых фрагментов; таблица specs создаётся кодом.
- Для числа в названии допускаем повтор только внутри точного названия; остальные числа проверяем по техническим полям и источникам. Проверки не доказывают смысл утверждений — это явно указано в README.
- Не более двух вызовов на запрос: исходный и одна корректировка качества; сетевые ошибки не повторяются.
- Лимит тела 64 KiB проверяется по фактически прочитанным чанкам ASGI; сообщения ошибок не содержат входные данные.
- Тесты используют настоящий SDK с httpx.MockTransport на границе HTTP; платные запросы отдельны.

## Risks / Trade-offs
- Смысловые выдумки → запрет в промпте, evidence, числовой фильтр, ручная сверка примеров.
- Слишком строгая проверка чисел → безопасный отказ после одной корректировки, без выдачи недостоверного результата.
- Пустой источник → needs_clarification; недостаточное описание может закончиться 502, без наполнения водой.
- Нет ключа → реальные примеры остаются незавершённой задачей.
