# Мутационное тестирование

Дата: 6 ноября 2026. База: `fee4e3228d79c9e6a484cca48aec7c257dbe4e6f`.
Инструмент: mutmut 3.8.1, Python 3.12.15, четыре процесса, forkserver.

## Результат

| Проверка | До усиления тестов | После |
|---|---:|---:|
| Обычные тесты | 51 | 85 |
| Автоматические мутации | 399 | 399 |
| Обнаружены тестами (killed) | 262 | 338 |

Score = killed / все 399 мутаций. Таймауты не засчитаны как killed, эквивалентные и косметические мутации не вычтены из знаменателя. Тесты дополнительно обнаружили 76 мутаций; прибавка — 19,0 процентного пункта. Ни одной мутации не исключали через pragma или фильтр ради повышения результата.

Дополнительно выполнены 20 точечных мутаций кода, пропущенного автоматическим инструментом: все 20 обнаружены. Все семь таймаутов также отдельно запущены с прямыми тестами ASGI и завершились обычным провалом теста. Эти перепроверки не меняют исходную статистику mutmut.

## Какие пробелы закрыты

- Проверка успешного ответа теперь обнаруживает исчезновение SEO-текстов, поисковых запросов и commercial-блока при сохранении status=ok.
- Прямые ASGI-тесты проверяют настоящий поток чанков, накопление общего размера, границу 65 536 байт, сборку тела, отключение клиента и повторное чтение. Генератор байтов через TestClient сам по себе не доказывал обработку нескольких ASGI-сообщений.
- Добавлены числовые форматы с запятой, Unicode-минусами, повтор всех разрешённых чисел, текст без чисел, регистр названия и ссылки evidence на каждый блок.
- Проверяется фактический запрос SDK: выбранная модель, непустые instructions, ограничение ответа, роли сообщений, JSON Schema и предыдущий ответ при исправлении.
- Раздельно проверяются отсутствие ключа/модели, разные признаки исчерпания квоты, объяснение ошибок и содержательная причина корректировки.
- Добавлены границы полей и числа характеристик, strict-вход, обрезание пробелов, источники фактов, регистр поисковых запросов, настройки таймаута/повторов и закрытие клиента.

Контрольная мутация таймаута выявила ошибку самого теста: assert внутри обработчика MockTransport перехватывался SDK и превращался в ожидаемый HTTP 502. Проверки перенесены за границу SDK, на записанный настоящий запрос; мутация timeout=46 вместо 45 после этого обнаруживается.

## Разбор 54 выживших

| Категория | Количество | Оценка |
|---|---:|---|
| Текст и регистр сообщений, оформление диагностики, допустимое имя схемы | 37 | Не фиксируем точную прозу тестами ради score |
| Эквивалентны для текущего публичного API и закреплённых зависимостей | 11 | Например, None вместо False в проверке истинности, другой нечисловой разделитель, неиспользуемый receive в JSONResponse, недостижимая третья итерация |
| Изменение текста недостижимого AssertionError | 4 | После двух попыток функция уже возвращает результат или выбрасывает ошибку |
| Защитный fallback внутреннего валидатора | 1 | Подробности ниже; глобальная эквивалентность не заявляется |
| Граница max_output_tokens: 5000 → 5001 | 1 | Один лишний токен не проверяется; наличие положительного ограничения проверяется |

`product_cards.generation.x_validate_draft__mutmut_20` заменяет fallback неизвестного source_field с пустой строки на XXXX. В публичном пути source_field ограничен enum существующих непустых полей конкретного товара, поэтому такой ответ модель не может вернуть по схеме. Но прямой вызов внутреннего валидатора с неизвестным полем и подходящей цитатой меняет поведение. Это оставшийся защитный пробел тестов, а не доказанно эквивалентная мутация. Производственный код ради метрики не менялся.

## Область проверки и ограничения

Автоматическая часть мутировала восемь функций в api.py, generation.py и schemas.py. Mutmut 3 пропускает декларации классов, константы и часть функций с декораторами; сам промпт, regex NUMBER, декларации Pydantic, validators и lifespan не покрыты этим автоматическим score. [Документация mutmut](https://mutmut.readthedocs.io/en/latest/).

20 дополнительных операторов проверили лимиты входа и выхода, strict/extra/strip, has_facts, регистр запросов, запрет оборванного заголовка, таймаут, повторы, утечку входа в ошибку и HTTP-статус. Это целевой набор, а не исчерпывающие мутации всех пропущенных строк. Для каждого использовалась отдельная временная копия без .env; исходный набор сначала успешно прогонялся в этой копии, затем менялась ровно одна проверяемая строка.

Семь исходных таймаутов связаны с нарушением ASGI-протокола и зависанием пути через TestClient. Отдельная проверка каждого с tests/test_body_limit.py завершилась exit code 1 с проваленным тестом, не таймаутом.

Платные вызовы OpenAI не выполнялись, .env в mutants/ не копировался. Смысловую точность реальной LLM этот прогон не проверяет. Сохранилось одно предупреждение Starlette о будущем переходе TestClient с httpx на httpx2; оно не скрыто.

## Как повторить

```bash
uv sync --locked
uv run pytest -q
uv run mutmut run 'product_cards.*' --max-children 4
uv run mutmut results
uv run mutmut show '<имя мутации из CSV>'
```

Явный шаблон заставляет повторить мутации, даже если уже есть кеш. Настроен также автоматический сброс результатов при изменении tests/**/*.py. Первый пробный запуск с кешем не пересчитал статистику; этот результат отброшен, итоговый прогон выполнен заново.

Дополнительные контрольные операторы записаны с точными before/after в mutation-extra-results.json: каждый применяется отдельно к временной копии, после чего запускается полный pytest. Перепроверки таймаутов выполнялись из mutants/ с MUTANT_UNDER_TEST=<идентификатор>, проектным Python и pytest tests/test_body_limit.py -q -x.

Полный список автоматических мутаций, исходных/итоговых статусов и классификации — mutation-results.csv. Производственные файлы product_cards/ не менялись: результат работы — усиленные тесты, инструмент и отчёт.
